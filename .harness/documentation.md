# 문서 관리 규칙

## 역할과 신뢰 경계

| 위치 | 역할 |
| --- | --- |
| AGENTS.md | 최소 공통 규칙과 조건별 탐색 진입점 |
| .harness/ | 작업 수행·검증 절차 |
| docs/ | 설계·계획·조사·점검 등의 입력 자료. 존재 자체로 검증된 사실이 되지 않음 |
| openwiki/ | 근거를 확인해 반영한 구조·동작·제약·중요한 결정 이유 |
| README.md | 하네스·위키를 바탕으로 작성하는 사람용 안내 |

- 상세 정보의 기준 위치는 하나만 유지한다. 운영 구성은 이 저장소에, 실험 분석과 Controller 내부 동작은 각각 담당 저장소에 둔다.
- AGENTS.md와 하네스에는 docs의 개별 파일·하위 디렉터리 링크나 탐색 경로를 두지 않는다. 현재 작업에서 지정한 자료는 입력으로 검토할 수 있다.
- 위키 부재를 이유로 미검증 자료를 검증된 지식으로 대체하지 않는다. 존재하지 않는 위키 링크를 만들지 않는다.
- 사용자 결정, 보고된 과거 확인 사항, 코드·설정, 실제 실행 결과를 구분한다. 현재 상태를 주장할 때에는 대상 환경과 검증 시점을 확인한다.
- 위키에 저장하는 행위 자체는 검증이 아니다. 설계 합의와 실제 동작 확인을 구분한다.

## 위키 갱신

- 명시적인 요청 시 입력 자료와 관련 설정·코드·결과를 확인해 영향받는 페이지만 갱신한다.
- OpenWiki 도구·스킬이 구성되어 있는지 먼저 확인한다. 미구성 상태에서 생성·갱신이 완료됐다고 보고하지 않는다.
- 계획·논의 전체를 복제하지 않는다. 확인된 책임, 관계, 제약, 선택 이유, 동작과 한계를 정리한다.
- 원본 입력은 작업 기록으로 보존한다. 생성된 위키의 수동 편집은 명시적 요청이 있을 때만 수행한다.
- 위키 내용만으로 하네스 규칙을 자동 변경하지 않는다. 작업 방식 변경은 별도로 합의한다.

## README

- AGENTS.md와 관련 하네스·위키를 근거로 작성한다. docs의 내용을 위키 등에 확인·반영하기 전에 직접 근거로 사용하지 않는다.
- 위키가 없으면 책임과 작업 방식 위주의 최소 안내를 유지한다. README를 채우기 위해 제품 지식을 하네스에 복사하지 않는다.
- README를 하네스·근거 문서·위키의 갱신 근거로 역참조하지 않는다.

## 검증

정보 누락·중복, 링크 유효성, 민감 정보, 계획·구현·검증 상태 구분, 하네스의 docs 개별 링크 부재를 확인한다. `git diff --check`를 실행하며 신규 파일도 검사 대상에 포함한다.
