# 작업 흐름

1. 현재 환경과 문제, 범위, 제약을 확인한다. 운영 변경은 읽기 전용 점검과 분리한다.
2. 접근 방식, 실패 상황, 되돌리기 방법과 검증 기준을 설계하고 리뷰한다.
3. 독립적으로 검증·리뷰 가능한 작은 변경 또는 PR로 나눈다.
4. 대상 context·namespace를 확인한 뒤 승인된 범위에서 구현한다. 가능한 검증은 개발 환경에서 먼저 수행한다.
5. 변경에 맞는 테스트·정적 검사·실행 점검을 수행한다. 실제 출력과 한계를 기록하며 민감 정보는 제거한다.
6. 리뷰·머지는 해당 세션에서 부여된 권한 안에서 수행한다. 이후 명시적인 위키 갱신 요청에 따라 검증된 결과를 반영한다.

현재 작업에 지정된 계획은 변경 제안이며 기존 동작의 증거가 아니다. 위키가 있으면 관련 페이지를 코드·설정과 대조하고, 없으면 지식 공백을 명시한다.

문서 배치, 근거 확인과 갱신은 [문서 관리 규칙](documentation.md)을 따른다. 수행하지 않은 검증은 완료로 기록하지 않는다.
